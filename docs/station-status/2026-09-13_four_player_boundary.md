# Station-status addendum — four-player PC+2 boundary

Date: 2026-09-13

Historical station maturity grades are unchanged. This pass changes the player-count policy, not the evidence grade for any station.

## CAPCOM

Remains an independent player function in the minimum supported PC+2 configuration.

Primary Apollo 13 organization material defines CAPCOM as the spacecraft communicator / crew voice contact. Combining that authority with INCO would erase a modeled coordination boundary between technical communications assessment and deliberate crew-facing transmission.

## INCO

Remains an independent player function in the minimum supported PC+2 configuration.

The selected PC+2 slice contains active communications-state reasoning: post-occultation link recovery, communications quality, high-bit-rate data, ranging/uplink availability, and related preparation activity. INCO therefore cannot currently be classified as safely omittable or facilitator-automatable without reducing scenario fidelity.

## FLIGHT

Remains independent from technical station bundles. Final decision authority is not merged with a station that supplies a readiness/recommendation judgment.

## Compact technical bundles

The previously approved bundles remain unchanged:

- LM SYSTEMS = TELMU + CONTROL
- FLIGHT DYNAMICS = GUIDO + FIDO/RETRO

Underlying station identities, products, readiness, actions, and audit provenance remain separate.

## Current minimum

At the present PC+2 fidelity target, the minimum supported human configuration is five players:

- FLIGHT
- CAPCOM
- LM SYSTEMS
- FLIGHT DYNAMICS
- INCO

This is a simulator boundary, not a historical Apollo staffing claim.
