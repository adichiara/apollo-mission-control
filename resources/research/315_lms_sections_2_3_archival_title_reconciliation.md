# Research note 315 — LMS handbook Sections 2 and 3 archival-title reconciliation

Date: 2026-09-18  
Status: **REPOSITORY EVIDENCE RECONCILED — SECTION TITLES/EXTENT ARE ARCHIVALLY CATALOGED; TECHNICAL CONTENTS AND MSC ACCESSION IDENTIFIERS REMAIN UNRECOVERED.**

## Question

Research note 313 established from a contemporaneous NASA/MSC engineering reference that `LMA790-2-LMS`, Volume II, Sections II and III existed and were dated 1 April 1967. Did the repository already contain stronger archival description of those sections than note 313 recognized?

## Result

Yes.

Research note 220 had already recovered the current Virginia Tech finding aid for the **James J. Avitabile Papers, Ms-2001-057**, which lists the LMS Instructor's Handbook at folder level.

Under Volume II the finding aid identifies:

- **Section 2 — Malfunction Data** — 3 folders;
- **Section 3 — Lunar-landing Mission Procedures** — 4 folders.

The same finding aid separately identifies:

- Section 4 — Instructor Activity for Interface Operation;
- Section 5 — Instructor Material;
- Section 6 — Scripting Data Sheets;
- Section 7 — Simulator Output Tables, 1 July 1967 — 3 folders.

Virginia Tech collection:

https://aspace.lib.vt.edu/repositories/2/resources/2187

Research note 313's NASA/MSC source remains valuable because it independently establishes that Sections II and III were actually cited as an engineering reference under `LMA790-2-LMS`, dated 1 April 1967. The Virginia Tech archival description supplies the section titles and folder extent that the NASA citation itself does not.

## Correct evidence boundary

### Documented

- NASA/MSC `MSC-IN-CF-P-69-5` / `NASA-TM-X-64471` cites `LMA790-2-LMS`, Volume II, Sections II and III, dated 1 April 1967.
- The Virginia Tech Avitabile finding aid identifies Section 2 as **Malfunction Data** and Section 3 as **Lunar-landing Mission Procedures**.
- The finding aid gives a three-folder extent for Section 2 and four-folder extent for Section 3.
- The Avitabile collection is open for research and accepts reproduction/digitization requests, as already documented in note 220.

### Still unresolved

The finding aid is archival description, not the handbook's technical text. It does **not** establish:

- individual malfunction definitions or insertion codes;
- mathematical/model ownership of any malfunction;
- which programs/machines implement a malfunction;
- exact lunar-landing simulator procedures;
- computer/program allocation;
- DDP-224 workload ownership;
- common-memory mapping;
- MSC accession identifier(s) for Sections 2/3;
- revision/effectivity of the physical folders beyond the catalog description;
- Apollo 13 applicability.

## Causal-engine relevance

The corrected titles make the retrieval priority more specific.

### Section 2 — Malfunction Data

Potentially high value for the causal-engine failure architecture because the title directly identifies malfunction material.

On recovery, extract only explicit fields such as:

`malfunction identifier -> affected subsystem/model -> insertion condition/method -> resulting indication/system effect -> applicable configuration/revision`

Do not assume the section uses that exact schema.

### Section 3 — Lunar-landing Mission Procedures

Potentially high value for integrated LMS operation during landing scenarios.

On recovery, extract only explicit simulator/instructor/crew procedure relationships, timing, configuration, and model/interface dependencies.

Do not infer that it is a software architecture manual from its title.

## Retrieval consequence

The highest-value archival request set now includes:

1. Volume I — Simulator Description (`67-14186`);
2. Volume II Section 2 — **Malfunction Data** (3 folders, Avitabile Papers);
3. Volume II Section 3 — **Lunar-landing Mission Procedures** (4 folders, Avitabile Papers);
4. Volume II Section 7 — **Simulator Output Tables** (3 folders, Avitabile Papers / corporate-index accession `67-16127`);
5. RG 255 E.155B1 acceptance/configuration material.

Section 2 rises in priority because its recovered title maps directly to the project's malfunction-insertion research question. That does not make its unrecovered contents authoritative yet.

## Repository correction

Research note 313 and its derived progress/status/catalog/roadmap records previously said the Section 2/3 titles were unknown. That statement is superseded by the already recovered note-220 archival evidence and must be retired repository-wide.

No runtime behavior, station product, model constant, or Apollo 13 configuration changes from this correction.
