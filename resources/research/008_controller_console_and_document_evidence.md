# Research Note 008 — Controller Console and Document Evidence

**Date:** 2026-09-11  
**Status:** REVIEWED-PARTIAL

## Findings

### Apollo 13 EECOM gives a concrete console anatomy example

Apollo 13 Review Board Appendix B illustrates the CSM EECOM console and identifies:

- precision TV monitor
- precision TV monitor
- Display Request Keyboard
- Manual Select Keyboard
- event indicators
- status/status-report keyboard
- summary-message-enable keyboard
- analog meter
- voice communication positions

The same section states that EECOM had multiple data formats and that its two most frequently used formats were updated once per second.

This is the best controller-specific console/display example located so far, but it belongs to Apollo 13.

### Universal CSM Console Handbook existed in Apollo 11 timeframe

A surviving edited transcription identifies:

**Universal CSM Console Handbook — S/C 106 and subsequent vehicles**  
Flight Control Division, Manned Spacecraft Center  
May 1969

Section D5, *Real-Time Commanding*, documents procedures for Universal Command Systems components on the EECOM systems engineer's MOCR console.

This is exactly the class of mission-era documentation needed for player procedures.

The original complete handbook has not yet been located digitally in this pass.

### Console handbooks were part of the formal flight-control method

NASA-SP-287 states that:

- procedures involving more than two console positions were placed in the Flight Control Operations Handbook
- personal procedures were placed in a Flight Controller Console Handbook prepared for each console position
- console handbooks described the controller's job and detailed procedures
- checklists were used where possible

This is strong evidence for the project's physical controller-document concept.

### Documentation development itself trained controllers

NASA-SP-287 also states that preparation of systems handbooks, mission rules, and procedural documents was itself an important training method.

Controllers learned:

- hardware capabilities and limitations
- consequences of alternate courses of action
- responsibilities of their position

This supports a simulation in which player mastery is partly mastery of the same structured reference material, rather than mastery of abstract game mechanics.

### Mission-period specialization

NASA-SP-287 states that integrated simulations concentrated on major mission periods including:

- launch through translunar injection
- lunar orbit insertion
- LM activation, checkout, and descent
- lunar surface operations
- ascent through rendezvous
- transearth injection
- reentry

It also states that specialized groups for these periods gave better support.

This matters when we later decide whether the same set of player roles should be used unchanged throughout an entire mission.
